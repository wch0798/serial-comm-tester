# 통신 테스트 도구 (시리얼 / TCP / Modbus)

Windows / Linux / macOS에서 쓰는 통신 테스트 프로그램입니다.
탭마다 연결을 하나씩 만들고, 연결마다 처리 방식을 고릅니다.

- **연결 방식**
  - 가상 시리얼: Windows에서는 COM 포트를 자동으로 만들고, Mac/Linux에서는 PTY를 씁니다.
  - 시리얼 포트(COM)
  - TCP 서버
  - TCP 클라이언트
  - UDP
  - CAN (가상 CAN, PCAN, Kvaser, Vector, IXXAT, slcan 어댑터, SocketCAN 등)
- **프로토콜**
  - 일반: "이 데이터가 오면 → 이 데이터를 보낸다" 규칙으로 자동 응답
  - Modbus 슬레이브: 장치를 흉내 냅니다. 요청이 오면 레지스터/코일 값으로 응답합니다.
  - Modbus 마스터: 요청을 보내고 응답 값을 표로 보여줍니다.
    - **폴링 목록**: 여러 값을 정한 간격으로 계속 읽습니다.
    - **실시간 그래프**: 필요할 때만 창으로 엽니다.
- **시험 도구**
  - 매크로 버튼
  - 반복 보내기
  - 체크섬·CRC 자동 계산
  - 중계·감시(스니퍼)
  - 시나리오 자동 실행
  - 오류 주입
  - Modbus 값 자동 변화
- **통신 로그**
  - 받은 데이터와 보낸 데이터를 색으로 구분해서 한 줄씩 보여줍니다.
  - 줄을 클릭하면 강조됩니다.
  - 파일로도 기록합니다.
- **설정 자동 저장**: 바꾼 내용은 몇 초 안에 자동으로 저장되고, 다음 실행 때 그대로 복원됩니다.
- **엑셀로 설정 만들기**: 엑셀 표에 설정을 써서 한 번에 불러오고, 현재 설정을 엑셀로 저장합니다.

## 실행 파일 받기 (Python 설치 불필요)

GitHub의 **Actions → 실행 파일 빌드** 또는 **Releases**에서 OS에 맞는 파일을 받아 압축을 풉니다.

| 파일 | OS |
|---|---|
| `SerialTester-windows-x64.zip` | Windows 10/11 (64비트) |
| `SerialTester-macos-arm64.zip` | Mac (Apple 칩: M1/M2/M3/M4) |
| `SerialTester-macos-x64.zip` | Mac (Intel 칩) |
| `SerialTester-linux-x64.tar.gz` | Linux (Ubuntu 22.04 이상 등, 64비트) |

압축 안에는 화면 프로그램(`SerialTester`), 자동 실행 프로그램(`SerialTesterCLI`), `실행방법.txt`가 들어 있습니다.
서명하지 않은 무료 프로그램이라 처음 실행할 때 경고가 뜰 수 있습니다. 넘어가는 방법은 `실행방법.txt`에 있습니다.

### 직접 실행 파일 만들기
```
pip install -r requirements.txt pyinstaller
python build.py
```
지금 쓰는 OS용 실행 파일이 `release/` 폴더에 만들어집니다. (Windows는 `build_windows.bat` 더블클릭)
`main` 브랜치에 올리면 GitHub가 4가지 OS용을 자동으로 만들고, 만든 실행 파일로 자동 시험(`samples/smoke_test.json`)까지 돌립니다.
`v1.0.0` 같은 태그를 올리면 Releases에 실행 파일이 올라갑니다.

## Windows에서 실행하기

### 방법 1: 실행 파일(.exe)로 나눠 주기 (사용자 PC에 Python 불필요)
1. Python이 설치된 PC 한 대에서 `build_windows.bat`를 더블클릭합니다. (또는 위의 "실행 파일 받기")
2. `release\SerialTester-windows-x64.zip`이 만들어집니다. 다른 PC에서 **압축을 통째로** 풉니다.
3. 다른 PC에서는 `SerialTester.exe`를 실행하면 됩니다.
4. 같은 폴더의 `SerialTesterCLI.exe`는 화면 없는 자동 실행용입니다 (아래 "자동 실행" 참고).

### 방법 2: Python으로 바로 실행
1. [python.org](https://www.python.org/downloads/)에서 Python을 설치합니다. 설치 첫 화면에서 **"Add python.exe to PATH"를 체크**하세요.
2. `run_windows.bat`를 더블클릭합니다. 처음 한 번은 필요한 구성 요소를 자동으로 준비합니다.

## Windows 가상 COM 포트 (자동)

**사용자가 따로 설정할 필요가 없습니다.**

1. 탭의 연결 방식을 **"가상 시리얼 (COM 자동 생성)"** 으로 고릅니다. Windows에서는 이게 기본값입니다.
2. **가상 포트 이름**에 다른 프로그램이 열 이름을 적습니다. 예: `COM10`
3. **☑ 사용**을 체크합니다.
   - 처음이면 com0com 드라이버 설치와 포트 생성을 한 번에 진행합니다. **관리자 권한 확인창이 한 번** 뜹니다.
   - "Windows 보안" 창이 뜨면 **"항상 신뢰"를 체크하고 "설치"** 를 누르세요.
   - 같은 이름의 포트가 이미 있으면 확인창 없이 바로 연결합니다.
4. 이제 다른 프로그램에서 `COM10`을 열면 이 프로그램과 연결됩니다.

### 가상 포트 관리 창 (상단 "가상 포트 관리…" 버튼)
- 만들어진 포트 쌍 목록을 보고, 삭제할 수 있습니다.
- **다른 프로그램 두 개를 서로 연결**할 때 쓰는 쌍(예: `COM20 ⇄ COM21`)을 추가할 수 있습니다.
- **상태 진단**: 드라이버가 Windows 보안 정책에 막혔는지 확인하고 해결 방법을 알려줍니다.
- 드라이버 설치와 제거도 여기서 합니다.

### 주의: 드라이버가 막히는 경우
- com0com은 무료지만 2011년에 옛날 방식으로 서명된 드라이버입니다.
- 최신 Windows 11(24H2 이상)이나 메모리 무결성이 켜진 PC에서는 막힐 수 있습니다. Windows 10은 영향이 적습니다.
- 막히면 프로그램이 원인을 진단해서 알려줍니다. 해결 방법(모두 무료):
  1. TCP로 시험할 수 있으면 TCP 서버/클라이언트를 사용합니다. 드라이버가 필요 없습니다.
  2. 테스트 전용 PC라면 Windows "테스트 모드"를 켭니다.
     - 관리자 명령 프롬프트에서 `bcdedit /set testsigning on`을 실행하고 재부팅합니다.
     - 보안 부팅을 꺼야 할 수 있습니다. 회사 보안 규정을 먼저 확인하세요.
  3. 메모리 무결성 때문이라면 Windows 보안 → 장치 보안 → 코어 격리 → 메모리 무결성을 끕니다.
  4. USB-시리얼 케이블 2개를 서로 연결(TX↔RX, GND↔GND)합니다.
- 함께 들어 있는 com0com은 **64비트(x64) Windows 전용**입니다.

Python 3.8 이상과 Tk 8.6 이상이 필요합니다.

```bash

```

```bash
python main.py
```

**macOS 주의**

- `brew install python-tk@3.13`으로 설치한 Python을 사용하세요.

## 설정 저장

- 탭, 연결 설정, 규칙, Modbus 값 등 **모든 설정이 자동으로 저장**됩니다. 바뀐 뒤 몇 초 안에 저장되고, 프로그램을 닫을 때도 저장됩니다.
- 다음에 실행하면 그대로 복원됩니다. **사용**이 체크돼 있던 연결은 자동으로 다시 열립니다.
- 저장 위치는 프로그램 폴더의 `vserial_config.json`입니다. 그 폴더에 쓸 수 없으면 사용자 폴더의 `.vserial\vserial_config.json`에 저장합니다.
- **다른 이름으로 저장 / 설정 불러오기**로 시험 항목별 설정 파일을 따로 만들어 바꿔 쓸 수 있습니다.
- 다른 OS에서 만든 설정 파일도 열 수 있습니다. 가상 시리얼은 그 OS 방식으로 바뀝니다.

### 시트 구성
| 시트 | 내용 (한 줄 = 한 항목) |
|---|---|
| 설명 | 작성 방법 |
| 연결 | 탭 하나 = 한 줄. 연결 방식, 포트, IP, 프로토콜, Modbus 장치주소, 마스터 요청 등 |
| 응답규칙 | 수신 데이터 → 응답 데이터, 형식, 검사값, 지연 |
| 매크로 | 이름, 데이터, 형식, 검사값, 반복 간격 |
| 시나리오 | 보내기 / 응답 확인 / 기다리기 단계 (위에서부터 순서대로) |
| Modbus값 | 슬레이브의 영역, 주소, 초기값 |
| 값자동변화 | 슬레이브 값 자동 변화 |
| 오류주입 | 탭별 오류 주입 확률 |

### 쓰는 법
- 다른 시트의 **탭이름**은 `연결` 시트의 탭이름과 똑같이 써야 그 탭에 들어갑니다.
- 연결방식, 프로토콜, 형식, 검사값, 영역, 방식처럼 정해진 값은 **드롭다운(▼)에서 고릅니다**.
- 사용 여부는 `O` / `X`로 씁니다. `예/아니오`, `Y/N`도 됩니다.
- 데이터 칸은 텍스트 서식이라 `0102` 같은 HEX가 숫자로 바뀌지 않습니다.
- 불러올 때 잘못된 줄은 건너뜁니다. 그리고 **"어느 시트 몇 행이 왜 틀렸는지"** 를 창으로 보여줍니다.
  - 예: `응답규칙 시트 5행: HEX에 0~9, A~F 가 아닌 글자가 있습니다: 'ZZ'`
- 로그 표시 설정 같은 화면 설정은 엑셀에 넣지 않습니다. 이런 설정은 자동 저장 파일(`vserial_config.json`)에 남습니다.

## 사용법

### 공통
1. **+ 새 연결**로 탭을 추가합니다.
2. 연결 방식과 프로토콜을 고르고 **☑ 사용 (연결 열기)** 를 체크합니다. 열린 탭은 제목 앞에 `●`가 붙습니다.
3. 오른쪽 로그에서 주고받은 데이터를 확인합니다.
   - RX: 수신 (파랑)
   - TX: 직접 보냄 (초록)
   - AUTO: 자동 응답 (주황)
   - MB: Modbus 해석 (보라)
4. 로그 아래 입력칸으로 데이터를 직접 보낼 수도 있습니다.

### TCP
- TCP 서버는 여러 클라이언트가 동시에 접속할 수 있고, 응답은 요청을 보낸 클라이언트에게만 갑니다.
- IP를 `127.0.0.1`로 두면 같은 PC 안에서만 접속됩니다. 다른 PC에서도 접속하게 하려면 `0.0.0.0`으로 바꾸세요.
- Mac/Linux에서 1024 미만 포트(예: Modbus 기본 502번)는 관리자 권한이 필요합니다.

### 일반 (자동 응답 규칙)
- 수신 데이터와 응답 데이터를 입력하고 **추가**를 누릅니다.
- `☑/☐` 칸을 클릭하면 규칙별로 켜고 끕니다. **자동 응답 사용** 체크박스는 탭 전체를 켜고 끕니다.
- 데이터 형식
  - TEXT: `AT\r`, `\x02DATA\x03` (`\r \n \t \0 \\ \xNN` 사용 가능)
  - HEX: `02 31 03`, `023103`, `0x02,0x31`
- 데이터가 여러 번에 나눠 들어와도 매칭됩니다.

### Modbus 슬레이브 (장치 흉내)
- **장치 주소**: 응답할 장치 번호입니다. 0으로 두면 모든 주소에 응답합니다.
- **영역**: 코일(0x), 입력 접점(1x), 입력 레지스터(3x), 보유 레지스터(4x)를 고릅니다. **값을 더블클릭**하면 수정합니다.
- 마스터가 쓴 값은 표에 바로 반영됩니다.
- **응답 지연**과 **응답 안 함(타임아웃 시험)** 을 설정할 수 있습니다.
- 지원 기능 코드: 01~06, 15, 16. 잘못된 요청에는 예외 응답(01, 02, 03)을 보냅니다.

### Modbus 마스터 (요청 보내기)
- 장치 주소, 기능 코드, 시작 주소, 개수를 넣고 **요청 보내기**를 누릅니다.
- 쓰기 기능(05/06/15/16)은 **쓰기 값**에 `100, 0x1F, -1` 또는 코일이면 `1,0,1`처럼 입력합니다.
- **주기 반복**, 응답 시간, 예외 코드와 뜻, 타임아웃이 표시됩니다.

### 프레임 (RTU / TCP)
- 시리얼이면 RTU, TCP면 Modbus TCP로 자동으로 정해집니다.
- "RTU over TCP" 장비는 프레임을 직접 RTU로 바꾸면 됩니다.

## 통신 로그

한 줄에 메시지 하나씩, 받은 것과 보낸 것을 색으로 구분합니다.

```
11:57:19.015 +209ms  ◀ 수신     [127.0.0.1:58109] 4B  ABCD  |  41 42 43 44
11:57:19.015 +0ms    ▶ 자동응답 [127.0.0.1:58109] 4B  \x01\x02\x81\xE1  |  01 02 81 E1
```

| 표시 | 색 | 뜻 |
|---|---|---|
| ◀ 수신 | 파랑 (줄 배경 하늘색) | 받은 데이터 |
| ▶ 송신 | 초록 (줄 배경 연두색) | 직접 보낸 데이터 (입력칸, 매크로, 시나리오) |
| ▶ 자동응답 | 주황 | 규칙 또는 Modbus 슬레이브가 자동으로 보낸 응답 |
| ▶ 중계 | 청록 | 중계 대상 탭에서 넘어와 이쪽으로 보낸 데이터 |
| ■ 해석 | 보라 | Modbus 요청과 응답 해석 |
| ⚠ 오류주입 | 분홍 | 오류 주입으로 망가뜨린 내용 |
| ▣ 시나리오 | 남색 | 시나리오 단계별 통과/실패 |

**표시 항목**
- 시간 옆의 `+209ms`는 바로 앞 줄과의 시간 간격입니다. 응답이 몇 ms 만에 왔는지 바로 보입니다.
- `[127.0.0.1:58109]`는 상대(TCP/UDP)이고, `4B`는 바이트 수입니다.

**한 줄 묶기**
- 시리얼은 데이터가 여러 조각으로 나눠 들어옵니다.
- 정한 시간(기본 20 ms) 안에 이어서 들어온 조각은 한 줄로 합쳐서 보여줍니다.
- 줄바꿈(`\n`)이나 CR(`\r`) 기준으로 나누는 방식도 고를 수 있습니다.

**도구**
- **보기 ▾**: 종류별로 보이기/숨기기를 하고, 시간 간격 표시와 자동 스크롤을 켜고 끕니다.
- **일시정지**: 화면만 멈춥니다. 그동안 들어온 내용은 풀면 이어서 나옵니다.
- **파일로 기록**: `logs` 폴더에 `탭이름_날짜.txt` 또는 `.csv`로 계속 기록합니다. CSV는 엑셀에서 바로 열립니다.
- 아래쪽에 수신/보냄 건수와 바이트 수가 표시됩니다.

## 시험 도구 (왼쪽 탭)

### 매크로
- 자주 보내는 데이터를 이름을 붙여 저장합니다. 검사값과 반복 간격도 함께 저장합니다.
- 저장한 매크로는 **로그 아래 버튼**으로 나타나서 한 번에 보낼 수 있습니다.
- **⟳ 반복 시작/정지**: 선택한 매크로를 정한 간격으로 계속 보냅니다. 여러 개를 동시에 반복할 수도 있습니다.

### 반복 보내기 / 검사값 (로그 아래 입력칸)
- **검사값**: 보낼 데이터 끝에 자동으로 붙입니다.
  - CRC16 Modbus, CRC16 CCITT-FALSE, CRC16 XMODEM, CRC8
  - 체크섬 1/2바이트, XOR(BCC), LRC, CRC32
- **반복 보내기**: 입력칸의 데이터를 정한 간격(ms)으로 계속 보냅니다.
- 자동 응답 규칙에도 "응답 끝에 검사값 자동 추가"를 쓸 수 있습니다.

### 중계 / 감시 (스니퍼)
- 상태 줄의 **중계 대상**에서 다른 탭을 고르면, 두 연결이 양방향으로 이어집니다.
  - 한쪽에서 받은 데이터는 그대로 다른 쪽으로 보냅니다.
- 오가는 데이터는 모두 로그에 남습니다.
  - 이쪽에서 받은 것: ◀ 수신
  - 저쪽에서 넘어온 것: ▶ 중계
- 연결 방식이 달라도 됩니다. 시리얼 ↔ TCP, 시리얼 ↔ UDP 등.
- 예: 프로그램 ↔ `COM10`(가상 시리얼 탭) ⇄ `COM3`(실제 장비 탭). 프로그램과 장비 사이의 통신을 중간에서 볼 수 있습니다.

### 시나리오
- 단계를 순서대로 자동 실행하고, 단계마다 통과/실패를 표시합니다.
- 단계 종류
  - **보내기**: 데이터를 보냅니다. 검사값을 자동으로 붙일 수 있습니다.
  - **응답 확인**: 직전에 보낸 뒤 받은 데이터에 기대값이 들어 있으면 통과합니다. 시간(ms)을 넘기면 실패입니다. 데이터를 비우면 아무 응답이나 통과입니다.
  - **기다리기**: 정한 시간만큼 기다립니다.
- 반복 횟수(0 = 무한)와 "실패하면 멈춤"을 정할 수 있습니다.
- 단계의 `☑/☐`를 클릭하면 그 단계만 건너뜁니다.
- 끝나면 결과 줄에 끝난 이유(완료 / 실패로 멈춤 / 사용자 정지 / 연결 끊김)와 통과·실패 수가 나옵니다.

## 시험 보고서 / 자동 실행

### 보고서 (엑셀)
시나리오 탭 아래 **"보고서"** 줄에서 씁니다.
- **보고서 저장…**: 마지막 실행 결과를 엑셀로 저장합니다.
- **끝나면 자동 저장**: 체크하면 시나리오가 끝날 때마다 `reports` 폴더에 자동으로 저장합니다.
  (파일 이름: `시험보고서_탭이름_날짜_시각.xlsx`)
- **보고서 폴더**: 보고서가 저장되는 폴더를 엽니다.

보고서 시트
| 시트 | 내용 |
|---|---|
| 요약 | 전체 판정(**합격 / 불합격**), 만든 시각, 실행 PC, 연결별 통과·실패 수, 회차, 끝난 이유, 걸린 시간 |
| 실패 목록 | 실패한 단계만 모아서 (몇 회차 몇 단계에서, 무엇을 받았는지) |
| 단계 결과 | 모든 단계의 결과 (회차, 걸린 시간 ms, 시각, 메시지) — 필터 사용 가능 |
| 통신 기록 | 시험 중 주고받은 데이터 (시각, 받음/보냄 구분, HEX, 텍스트) |

판정은 "끝까지 실행했고 실패가 하나도 없을 때"만 합격입니다. 사용자가 중간에 멈추거나 연결이 끊기면 불합격입니다.

### 자동 실행 (화면 없이)
출하 검사, 반복 시험, 밤새 돌리는 장시간 시험처럼 화면을 지켜볼 필요가 없을 때 씁니다.
상단 **"자동 실행 명령"** 버튼을 누르면 지금 설정으로 실행하는 명령이 나오고, **"명령 복사"**로 바로 복사할 수 있습니다.

```
# Windows (실행 파일)
SerialTesterCLI.exe vserial_config.json

# Windows (Python으로 실행할 때)
autotest_windows.bat vserial_config.json

# Mac / Linux
.venv/bin/python autotest.py vserial_config.json
```

- 화면에서 쓰던 설정 파일(`.json`)이나 엑셀 설정 파일(`.xlsx`)을 그대로 씁니다.
- 기본으로 **'사용' 체크된 탭을 모두 열고**, 그중 시나리오 단계가 있는 탭의 시나리오를 동시에 실행합니다.
  (응답 규칙, Modbus 슬레이브, 값 자동 변화, 오류 주입, 중계 설정도 화면과 똑같이 동작합니다.)
- 보고서는 설정 파일 폴더의 `reports`에 저장됩니다.

| 옵션 | 뜻 |
|---|---|
| `--tab 이름` | 이 탭의 시나리오만 실행 (여러 번 쓸 수 있음) |
| `--repeat 100` | 반복 횟수 바꾸기 |
| `--repeat 0 --max-time 3600` | 1시간 동안 계속 반복 (장시간 시험, 실패 없으면 합격) |
| `--max-time 초` | 전체 제한 시간 (정해진 횟수를 못 끝내면 불합격) |
| `--wait 3` | 연결 후 3초 기다렸다가 시작 (장비 부팅 시간 등, 기본 1초) |
| `--report 결과.xlsx` | 보고서 저장 위치 지정 |
| `--no-comm` | 통신 기록 시트 빼기 (장시간 시험에서 파일 크기 줄이기) |
| `--quiet` | 실패한 단계와 결과만 화면에 표시 |
| `--list` | 설정 파일의 탭 목록만 보기 |

끝날 때 돌려주는 값: **0 = 합격, 1 = 불합격, 2 = 설정/연결 오류**
배치 파일에서는 `%ERRORLEVEL%`, Mac/Linux 셸에서는 `$?`로 확인해서 다음 작업(예: 불합격이면 알림)을 정할 수 있습니다.

> 화면 프로그램에서 같은 포트를 열어 둔 채로 자동 실행하면 포트를 열 수 없습니다. 화면 쪽 연결을 먼저 닫으세요.

### 오류 주입
- 자동 응답(규칙, Modbus 슬레이브)을 일부러 망가뜨려서, 상대 프로그램이 오류를 잘 처리하는지 시험합니다.
- 항목마다 확률(%)을 정합니다.
  - 응답 안 함
  - 데이터 변조 (CRC 오류)
  - 잘라 보내기
  - 두 번 보내기
  - 쓰레기 바이트 붙이기
  - Modbus 예외 응답 (예외 코드 선택)
  - 무작위 추가 지연
- 켜져 있으면 탭 이름 앞에 `⚠`가 붙고, 망가뜨릴 때마다 로그에 `⚠ 오류주입`으로 남습니다.

### Modbus 값 자동 변화 (슬레이브 → "값 자동 변화" 탭)
- 주소마다 값이 저절로 바뀌게 합니다. 실제 센서처럼 움직이는 값을 시험할 때 씁니다.
- 방식: 증가, 감소, 무작위, 사인파, 토글(최소↔최대)
- 최소/최대 범위와 바뀌는 간격(ms)을 정합니다. 음수 범위도 됩니다.

### UDP
- **내 IP/내 포트**: 받을 주소입니다.
- **상대 IP/상대 포트**: 보낼 곳입니다.
  - 비워 두면 마지막으로 보낸 쪽으로 보냅니다.
  - 자동 응답은 항상 보낸 쪽으로 돌아갑니다.
- Modbus를 고르면 기본 프레임은 Modbus TCP(MBAP) 형식입니다.

## Modbus 폴링 목록 / 실시간 그래프

Modbus 마스터 탭의 **"폴링 목록"** 에서 씁니다.

### 폴링 목록
읽을 값을 한 줄씩 등록하면, 정해진 간격으로 계속 읽어 표에 보여줍니다.

| 칸 | 설명 |
|---|---|
| 이름 | 값 이름 (예: 온도) |
| 장치 | Modbus 장치 주소 |
| 기능코드 | 01 코일 / 02 입력 접점 / 03 보유 레지스터 / 04 입력 레지스터 |
| 주소 | 0부터 시작하는 번호. 표에는 PLC 주소(예: 40001)로도 보입니다 |
| 형식 | 비트, UINT16, INT16, UINT32, INT32, FLOAT32 |
| 순서 | 32비트 값의 바이트 순서. ABCD(기본), CDAB(워드 스왑), BADC, DCBA |
| 배율/오프셋 | 화면 값 = 읽은 값 × 배율 + 오프셋. 예: 배율 0.1 → 253 이 25.3 |
| 간격(ms) | 몇 ms마다 읽을지 |

**실행**
- **▶ 폴링 시작**을 누르면 값과 상태(`OK 12ms`, `타임아웃`, `예외 02` 등)가 계속 바뀝니다.
- 요청은 **한 번에 하나씩** 보내고 응답을 기다립니다.
  - 그래서 RTU(시리얼)에서도 요청이 서로 엉키지 않습니다.
  - "단일 요청" 화면의 요청도 같은 순서에 끼워 넣습니다.
- 값이 실패하거나 다시 정상이 될 때만 로그에 남깁니다. 매번 남기면 로그가 너무 많아지기 때문입니다.

### 실시간 그래프 (필요할 때만)
- **그래프 보기**를 누르면 별도 창으로 열립니다. 닫으면 그리기를 멈춥니다.
- 폴링 목록에서 **그래프** 칸이 ☑인 항목만 그립니다.
- 그래프 창 기능
  - 시간 범위: 10초~30분
  - 일시정지
  - Y축 자동/직접 지정
  - 기록 지우기
  - CSV 저장
- 그래프 창을 닫아 두어도 값 기록은 계속되므로, 나중에 열면 지난 값부터 보입니다.

## CAN 통신

연결 방식을 **CAN**으로 고르면 됩니다.

### 인터페이스
| 인터페이스 | 채널 예 | 필요한 것 |
|---|---|---|
| 가상 CAN (프로그램 안 탭끼리) | vcan0 | 없음. 장비 없이 시험할 때 (같은 채널 이름 탭끼리 연결) |
| 가상 CAN (네트워크) | 239.74.163.2 | 없음. 같은 네트워크의 다른 PC와 (멀티캐스트, 네트워크 환경에 따라 안 될 수 있음) |
| 시리얼 CAN 어댑터 (slcan) | COM5 | CANable, USBtin 같은 저가 어댑터 |
| PCAN | PCAN_USBBUS1 | Peak 무료 드라이버 (PCAN-Basic) |
| Kvaser / Vector / IXXAT | 0 | 각 제조사 무료 드라이버 |
| candleLight (gs_usb) | 0 | candleLight 펌웨어 어댑터 |
| SocketCAN | can0 | Linux 전용 |

### 데이터 쓰는 법 (형식: CAN)
- `123#01 02 03`: 표준 ID 0x123, 데이터 3바이트
- `18FF50E5#11 22`: 확장 ID. 4자리 이상이거나 7FF보다 크면 확장 ID입니다.
- `123#01; 456#02 03`: 여러 프레임은 `;`로 구분합니다.
- 데이터는 최대 8바이트입니다. 검사값·줄끝은 붙이지 않습니다. CAN CRC는 장치가 계산합니다.

### 사용 예
- **응답 규칙**: 수신 `7DF#02 01 0C` → 응답 `7E8#04 41 0C 1A F8`
  - 수신을 `123#`처럼 데이터 없이 쓰면 "ID 123이면 데이터 상관없이"라는 뜻입니다.
- **매크로**: 하트비트 `700#05`를 1000ms마다 반복 보내기
- **시나리오**: `7DF#02 01 0C` 보내기 → `7E8#04 41 0C` 응답 확인
- **중계**: CAN 탭과 TCP 탭을 이으면 CAN 프레임이 `123#01 02` 글자 줄로 TCP에 오갑니다. CAN↔네트워크 게이트웨이로 쓸 수 있습니다.

로그에는 `ID 7E8 [5] 04 41 0C 1A F8`처럼 ID, 길이, 데이터로 보입니다.

**참고**: CAN은 "일반 (자동 응답 규칙)" 프로토콜로만 씁니다. CAN 위의 Modbus는 지원하지 않습니다.

## 화면 사용 팁

**로그 줄 강조**
- 줄을 클릭하면 노란색으로 강조됩니다.
- **Ctrl(맥은 ⌘)+클릭**으로 여러 줄을 주황색으로 표시해 둘 수 있습니다.
- **Esc**를 누르면 강조를 지웁니다.
- **줄 복사** 또는 Ctrl+C로 강조한 줄을 복사합니다.

**화면 크기**: 창 크기는 실행할 때 화면이 잘리지 않는 폭으로 자동으로 맞춥니다.

**상단·하단 줄**
- 상단 제목 줄 오른쪽에 마지막 자동 저장 시각이 보입니다.
- 하단 상태 줄에는 열린 연결 수와 로그 폴더가 보입니다.
